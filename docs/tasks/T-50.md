# T-50 · Quản lý CRUD khoa và tài khoản trường

## Mục tiêu
Admin quản lý danh mục khoa và danh sách tài khoản, chọn khoa bằng combobox.

## Ngữ cảnh cần biết
Cùng email có nhiều vai trò riêng. Giữ ID, lịch sử và hồ sơ đã nộp; đơn vị quản trị/Đào tạo không nhất thiết là khoa thống kê.

## Phạm vi
**Trong:** migration danh mục, API CRUD admin, UI form/list/sửa/xóa, combobox, thống kê tên khoa động.
**Ngoài:** xóa dây chuyền bảng điểm, thay API daotao/triển khai.

## Đầu vào đã có
users/courses/submissions/audit, API admin và dashboard thống kê.

## Việc phải làm
Khởi tạo danh mục 5 khoa và đơn vị cũ một lần. Thêm/sửa tên/xóa khoa chưa dùng; mã ổn định. Tạo/sửa tên,email,role,khoa,mật khẩu tùy chọn,active,fingerprint; không trả password. Cấm tự xóa/khóa/mất admin; chặn xóa tài khoản đã có liên kết và chuyển vai trò/khoa phá phân công. Invalidate sessions khi sửa. UI xác nhận xóa cụ thể và báo lỗi server, không gửi mutation khi cancel.

## Quy ước bắt buộc
Admin-only, CSRF, SQL tham số, audit không secrets. Thay password chỉ khi nhập mới; role theo email riêng. Không sửa PDF/history và chỉ sửa touches.

- [x] API CRUD/quyền/CSRF/trùng/liên kết/password/migration đạt
- [x] Typecheck/template/DAG đạt
- [x] E2E CRUD/combobox/ảnh đạt
- [x] Sao lưu trước migration live, website restart và docs/flow cập nhật

## Test phải viết
Khoa CRUD idempotent seed/tên thống kê động; khoa đang dùng cấm xóa; account CRUD/trùng email-role/password trống giữ nguyên; role/khoa có phân công cấm đổi; tự xóa/khóa/đổi role admin cấm; RBAC/CSRF; E2E thêm sửa xóa và combobox.

## Định nghĩa "xong"
Admin CRUD khoa/tài khoản hoạt động, dữ liệu lịch sử giữ nguyên và tests đạt.

## Cạm bẫy đã biết
Không seed lại khoa đã xóa khi restart; không xóa audit hoặc FK; cùng email khác vai trò được phép.
